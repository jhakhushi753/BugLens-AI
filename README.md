🔍 BugLens AI - Intelligent Test Failure Analysis

A runnable ShopSphere storefront and BugLens investigation dashboard prototype. The current investigator uses evidence-based local rules and browser storage; it does not yet connect to Claude or a database.

ShopSphere failure → captured evidence → BugLens report → source export

For the implemented service setup and QA workflow, see [DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md) and [apps/shopsphere/README.md](apps/shopsphere/README.md).

🐛 The Intentional Bugs

ShopSphere is a working e-commerce sample with four deliberately introduced QA defects:

Bug #1: Incorrect Cart Total 🔴 HIGH

Function: `cart_snapshot()` in `apps/shopsphere/backend/main.py`

python
# ❌ BUGGY CODE
subtotal = round(sum(line["product"]["price"] for line in lines), 2)

# ✅ SHOULD BE
subtotal = round(sum(line["product"]["price"] * line["quantity"] for line in lines), 2)

Test: test_cart_total_calculation() Impact: Users see wrong totals, may abandon checkout

Bug #2: Payment API Failure with Coupon 🔴 HIGH

Function: `charge()` in `apps/shopsphere/payment-mock/main.py`

python
# ❌ BUGGY CODE
if request.coupon_code:
    if random.random() < 0.6:  # 60% failure rate
        raise HTTPException(status_code=500)

# ✅ SHOULD PROCESS SUCCESSFULLY

Test: test_checkout_with_coupon() Impact: ~60% of coupon purchases fail with 500 error

Bug #3: Broken Error Handling 🔴 HIGH

Function: `checkout()` in `apps/shopsphere/backend/main.py`

python
# ❌ BUGGY CODE
except Exception as e:
    logger.error(f"Payment processing failed: {str(e)}")
    # Bug: Order status not set, cart cleared anyway

# ✅ SHOULD HANDLE PROPERLY

Test: test_checkout_payment_failure() Impact: Failed payments leave orders in inconsistent state

Bug #4: Reversed Frontend Price Sort

Selecting "Price: low to high" sorts the catalog from high to low. The storefront posts evidence to the ShopSphere API on first selection.

🚀 Key Features
🤖 Evidence-Based Failure Reports
Imports starter scenarios and captured failures from ShopSphere
Uses deterministic local rules to classify evidence and flag human review
Exports structured JSON reports; remote AI analysis is not connected
📊 Classification
APPLICATION_BUG: Code defect in app
TEST_BUG: Issue with test itself
FLAKY: Intermittent failure
ENVIRONMENT: Missing setup/config
EXTERNAL_SERVICE: API/network failure
💡 Confidence Scoring
0.95-1.0: Stack trace clearly shows cause
0.80-0.94: Strong evidence
0.60-0.79: Reasonable inference
<0.60: Uncertain, needs more data
📈 Severity Levels
CRITICAL: Crash, data loss
HIGH: Core feature broken
MEDIUM: Feature partially broken
LOW: Cosmetic issue

💡 Key Concepts
Prompt Template

The prompt templates describe the planned AI-backed investigator. The current dashboard uses local rules; see [buglens-prompt-template.md](buglens-prompt-template.md) for the future model contract.

Test-Driven Bug Discovery
Write test that should pass
Run test (it fails due to bug)
Failure evidence is posted to ShopSphere
Import the evidence in the BugLens dashboard
Developer fixes bug
Test passes ✅
Failure Evidence Chain
Test Execution
    ↓
Capture: Error message
         Stack trace
         Screenshots
         Console logs
         Source code
    ↓
Post to ShopSphere evidence endpoint
    ↓
Import into BugLens dashboard
    ↓
Local classification + confidence
    ↓
Saved in browser storage
